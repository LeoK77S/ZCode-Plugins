# suian-side-editor

**本机已有 UTF-8 文本的独立侧栏编辑器与选区评论**：提供目录树、临时与固定页签、手动与自动保存、外部冲突处理和会话恢复。安装方法见下文，功能变化见[更新记录](CHANGELOG.md)。

文本编辑不依赖网关，选区评论需要已有网关和桌面端远控连接。**选区评论尚未完成 ZCode 3.16 兼容验证**，具体使用限制见“临时选区评论”一节。当前不支持 PPT、远程工作区及文件管理，编辑器仍待完整首版验证与用户验收。

## 功能行为

- 在本机工作区的已有会话中打开“文本编辑器”。无法确认当前会话或工作区时，文件访问保持禁用。
- ZCode 3.16 的会话含多个本机目录时，可在右侧文件树上方切换目录；左上角显示当前目录的完整路径。旧版单目录会话沿用原有行为。
- 只访问当前会话允许的目录，不接受范围之外的路径或链接。会话已固定附加目录时，以该范围为准。
- 读取 UTF-8 文本时识别 BOM 和换行格式；文件不存在、编码不支持或权限不足时，会显示具体错误。

- 顶部文件夹按钮开关右目录树，node_modules、隐藏文件与无扩展名文件可浏览。主区域按右树之外的剩余宽度居中。
- 单击复用一个斜体临时页；双击或首次编辑固定为正体。已打开文件只激活，保存后保持固定。
- 保存按钮和 Ctrl+S 写回当前正文；磁盘版本不符则拒绝。保存等待期间新增编辑仍未保存，失败保留正文。关闭脏页提供保存并关闭／放弃修改／取消。

- 内部保存方式按钮切换手动与自动，首次默认为手动。切换后会记住当前会话的选择；其他已有会话保留各自模式，新会话继承最新默认。
- 自动模式在停止输入 800 ms、切换内部页签和切入自动模式时尝试保存；切手动取消尚未开始的任务。写回仍走同一内容版本检查入口。
- 打开的文件会跟随外部变化。首次打开仍需正常权限审批，之后接收该文件的更新，无需重复审批。没有未保存编辑时，正文自动刷新并保留有效阅读位置；存在未保存编辑或读写失败时，保留正文并暂停该文件的自动保存。重新读取前，需要确认放弃当前编辑。

- 会话状态保存为恢复副本并按会话相互隔离：页签顺序、临时／固定属性、当前页、每文件阅读位置与未保存正文写入插件自有数据库。页面显示副本待同步、成功或失败；只有回执到达才确认副本已同步。编辑器关闭重开、页面被宿主回收重建、应用重启后都从副本恢复；恢复遇磁盘冲突或读权限失败保留脏正文，干净文件重新读取最新磁盘内容。
- 切换目录前先保存恢复副本；保存中暂不能切换。各目录分别保留页签和未保存正文，同名文件不会混用。切换浏览目录不会切换主对话或改变会话的执行目录。
- 会话取消某个附加目录后，已打开文件也会停止读取该目录的新内容并显示原因；页面已有正文保留。重新授权并确认重读后，继续同步外部修改。

## 临时选区评论

在文件正文中选择文本，点击“评论选区”，填写后加入当前主对话。评论会保留当时的文件路径、行号、选文和未保存标记。添加评论不会保存源文件，后续编辑也不会改变已添加的评论。多条评论集中显示在同一个主对话胶囊中，模型回复留在主对话。

评论状态首次登记需要权限审批，之后自动同步。插件确认对应评论已被当前会话受理后，才会清理该批评论；无法确认时保留评论。关闭或重建编辑器不会自动重新发布旧胶囊。

**评论可能重复发送**：若插件受理一条评论后、下次检查前，该评论被外部取消，且当前对话已不再显示排队内容或用户输入，这条评论可能随下一条新评论一起再次发送给模型。仅靠禁用按钮无法完全避免这一风险，处理进展见 [#57](https://github.com/ONEGAYI/ZCode-Plugins/issues/57)。

**模型回复等待期间会禁用评论发送**：评论按钮和已打开表单的提交均被禁用，未提交正文与选区保留。状态未知或断连时显示具体原因，文件编辑和保存继续可用。状态判断可能迟到，上一条评论的发送与清理仍可能影响新评论，无法保证同时操作时始终安全。

评论需要已有公共网关和桌面端远控连接，尚未完成 ZCode 3.16 兼容验证；文本编辑功能不依赖网关。监听主对话状态可能启动或恢复当前会话的运行环境，不会创建辅助会话。取消监听时会等待确认；超时或断连时，会明确报告无法确认监听是否已结束。

## 原生安装与打开

要求 Node.js 24+、ZCode 应用版本至少 3.15.1，以及 MCP Apps 能力和可信会话归属。在原生插件管理器中安装并启用本仓库市场中的 `suian-side-editor`，其公共依赖 `suian-zcode-common` 一并安装。市场下载不会执行 npm；首次安装及每次更新后使用 [setup 技能](skills/setup/SKILL.md) 准备锁定依赖和公共包链接。

Agent 会先核对实际安装位置、数据目录和启用状态。文本编辑器只需准备依赖和公共包链接；评论另需已有网关和桌面端远控连接，setup 不会自动安装或重启网关。编辑器页面随插件提供，用户无需自行构建。

完成 setup 后，在本机工作区的已有会话中打开侧栏“打开标签页”，选择“文本编辑器”。顶部文件夹按钮可展开右侧目录树；选中文件后编辑，使用内部保存方式按钮选择手动或自动。首次读取与保存等操作仍经过宿主正常权限审批；缺可信会话时禁用文件访问。

会话状态保存在插件自己的数据目录，更新插件缓存不会清除这些数据。更新代码或公共包链接后，已经运行的编辑器服务仍可能使用旧代码，需要按 setup 核对并重新连接。

## 本地开发

要求 Node.js 24。只在本插件目录安装依赖；安装后通过公共入口建立包链接，不能假设正式插件缓存互为同级目录：

```powershell
npm ci --ignore-scripts
node ../suian-zcode-common/link.mjs --plugin-root . --runtime-root ../.scratch/common-runtime
npm run build
npm test
npm run check
```

上面的相邻源码路径只用于源码开发时调用公共链接入口。正式独立缓存使用 common 自身的稳定 `link.mjs` 入口，以插件根和公共运行时位置为参数；本插件运行代码始终按 Node 包名导入 common。

浏览器烟测使用开发环境提供的 Playwright。可把 `SUIAN_SIDE_EDITOR_PLAYWRIGHT_MODULE` 设为该环境的 `playwright/package.json` 绝对路径，再运行 `npm run test:browser`。测试运行服务端实际返回的构建 HTML 与 SDK 服务，但宿主 meta 是夹具注入，不能替代 Native 验证。

状态数据库为宿主默认注入的 `ZCODE_PLUGIN_DATA` 目录下的 `editor-state.sqlite`。源码直跑时必须显式提供自己的外置测试数据目录；缺失或无效目录不回退到工作区、插件缓存或 common。schema 2 在写事务内迁移 schema 1，保留已有全局默认和会话模式，并按可信工作区／会话隔离恢复副本。设置、副本与源文件各自显示回执，互不冒充。Node 24 内置 SQLite，无新增 ORM 或运行依赖。

UI 源文件是 `ui/editor-template.html`、`ui/editor.css` 与 `ui/editor.mjs`。`npm run build` 生成自包含的 `ui/dist/editor.html` 和第三方许可；本次 bundle 的完整版权与许可文本同时嵌入返回 HTML，并保留独立许可文件。生成内容随插件提交，不直接手改，也不从 CDN 加载编辑器。

资源 URI 只指向首次受审工具已经登记的文件，不解析成新文件路径。资源请求没有 ZCode 对话 meta，归属来自首次登记；不能声称服务端逐次验证资源读者的 SID。资源为当前进程的只读快照，退订或服务关闭后登记失效，重建必须经工具重新打开。保存与模式写入继续走原受审工具。

## 验证记录与限制

SE-01 至 SE-05 及评论保护的开发验证过程按票记录在[实施总记录](docs/development-verification.md)，覆盖各阶段的 SDK、实际构建浏览器与原生 Desktop 检查；各票的验证明细与脱敏证据是同目录的 `se0*-verification.md` 与 `se0*-evidence.json` 系列。规格与票目拆分见[首版规格](docs/text-editor-spec.md)与[票目清单](docs/text-editor-tickets.md)。原生检查目前是人工审批的限定烟测，不等同用户产品验收；编辑器整体尚未通过完整首版和用户验收。

读取与保存使用常规 `realpath`、文件句柄和字节版本。保存前核对内容并在本服务接收入口顺序处理，不提供跨任意外部编辑器的原子比较写入，也不保证工作区目录被并发替换时的原子路径隔离。
