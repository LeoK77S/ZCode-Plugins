# suian-side-editor 首版规格

日期：2026-10-12。状态：需求共识、规格与票粒度已由用户批准，并授权发布 11 张 Issues；尚未实施运行代码或通过宿主验收。

## 问题与目标

用户需要在 ZCode 侧栏直接编辑工作区文本，并把对某段文字的评论交给当前主对话。现有插件工件页面是本仓库实现的只读页面，不能据此断言宿主禁止可编辑插件页面。

新建独立插件 `suian-side-editor`。编辑器、文件页签、保存与评论业务由该插件承担；确有复用需求的基础实现放在 `suian-zcode-common`。

**首版完成标准**：在受支持的真实 Desktop 中，从独立插件入口完成文件浏览、编辑、保存、恢复及主对话评论流程。发送等待期间的新评论必须保留，只有本次提交的评论被清理。源码调研、夹具测试或局部编辑器可用均不能代替这个完成标准。

## 已确认的用户故事

1. 作为 ZCode 用户，我希望直接打开独立编辑器侧栏，以便浏览文件而无需先向模型发消息。
2. 作为用户，我希望通过顶部文件夹按钮打开右侧目录树，以便按目录找到文件，包括 node_modules 中的文件。
3. 作为用户，我希望编辑区域按目录树之外的剩余宽度居中，以便展开目录树时布局仍然自然。
4. 作为用户，我希望单击文件以斜体临时页打开，以便连续浏览时复用一个未编辑页面。
5. 作为用户，我希望双击文件或首次编辑后将页面固定为正体页签，以便后续单击不会替换它。
6. 作为用户，我希望用保存按钮或 Ctrl+S 保存，以便在手动模式下明确控制写回。
7. 作为用户，我希望自动模式在停止输入 800 ms、切换内部页签和切入自动模式时尝试保存，以便减少重复操作。
8. 作为用户，我希望当前会话的保存选择持久化并更新新会话默认值，同时保留其他已有会话的选择，以便各会话互不干扰。
9. 作为用户，我希望外部修改在没有未保存编辑时刷新，有未保存编辑时提示冲突并暂停写回，以便避免覆盖双方修改。
10. 作为用户，我希望关闭插件或重启应用后恢复页签、未保存正文、焦点页面和阅读位置，以便继续之前的工作。
11. 作为用户，我希望关闭未保存文件页时可选保存并关闭、放弃修改或取消，以便控制修改去留。
12. 作为用户，我希望评论完整保存创建时的文件路径、标题、行号、选文和评论，以便模型准确理解位置与意图。
13. 作为用户，我希望可评论未保存内容并看到明确标记，以便区分编辑正文和磁盘正文。
14. 作为用户，我希望评论进入主输入框上方的聚合胶囊，以便在主对话正常发送并接收回复。
15. 作为用户，我希望发送受理后自动清理已提交评论，失败时保留，以便重试且不重复带入旧评论。
16. 作为用户，我希望发送等待期间继续添加评论，新评论保留给下一条消息，以便保持与原生一致的使用体验。

## 范围

首版支持当前本机工作区内已有的 UTF-8 文本文件，包括 Markdown、代码、TXT 以及符合文本条件的其他文件。按需展开目录，不递归预扫 node_modules，不新增扩展名白名单或用户未要求的目录过滤。

首版不包括 PPT、远程工作区、新建／重命名／删除文件、辅助问答、插件内模型回复、替换宿主原生 PreviewPane 或外层文件页签。远程与文件管理各保留一张后续特性票。

## 布局与页签契约

视觉以用户要求的 Codex 侧栏编辑器为参考：紧凑的内部顶栏与文件页签，编辑区为主体，颜色与字体协调当前宿主主题。实际可用主题信息在原生页面集成时核实。

- 插件页面主体为编辑器；内部顶栏显示文件页签、文件夹按钮、保存方式与保存状态。
- 右侧目录树独占自身宽度；编辑主区域使用剩余宽度，内容居中不得以整个侧栏宽度计算。
- 目录按需读取；node_modules 与其他隐藏文本文件可浏览。目录项与不可编辑文件不得被误当成可保存正文。
- 同时最多一个临时页。单击尚未打开的文件替换未编辑临时页；单击已打开文件只激活该页。
- 双击固定文件页；首次编辑立即固定。固定后即使保存为干净状态，也不自动退回临时页。
- 关闭有未保存编辑的内部页签：保存并关闭／放弃修改／取消。保存失败或冲突时保留页签。
- 原生外层插件面板由宿主关闭，插件页面不能阻止；恢复不得只依靠关闭回调。
- 焦点页面指内部当前文件页；恢复它不要求抢走主对话输入框的键盘焦点。

## 文件读写与冲突契约

文件读写只通过绑定当前工作区的服务端工具进行。浏览器提供工作区内相对路径；服务端验证解析后的目标仍在可信工作区内，不允许借绝对路径、路径穿越或指向外部的链接越界。

读取结果包括正文、规范路径、原编码特征和磁盘版本标识。版本标识基于实际文件内容，不能只依赖可能重复的 mtime。非法 UTF-8、二进制内容、权限失败或已删除文件明确报错，不能用替换字符解码后保存。

保存请求包含正文与读取／最近成功保存时的基线版本。服务端重新检查实际磁盘版本，不匹配则拒绝写回并报告冲突。同一插件的写回按文件顺序处理，晚到的旧响应不能把新编辑标为已保存。

未修改的文本保存不应改变 BOM、换行或其他原有字节特征。编辑后的保存维持原有编码与换行约定。保存成功只表示该次正文已写回；此后新增编辑仍为未保存。

已打开文件发生外部修改时：

| 当前状态 | 行为 |
| --- | --- |
| 没有未保存编辑 | 自动重新读取并更新正文、版本；保留有效的阅读位置 |
| 存在未保存编辑 | 保留本地正文，提示冲突，暂停该文件自动保存 |
| 用户选择重新读取 | 明确放弃当前编辑后读取磁盘正文 |
| 用户选择保留编辑 | 保留正文和冲突状态；不把保留理解为授权静默覆盖 |

版本检查是保存前置条件；不能声称普通文件读后写天然具有跨任意外部编辑器的原子比较写入能力。实施验证须明确实际文件操作提供的保证。

## 保存模式与恢复契约

首次默认手动。新会话首次使用编辑器时读取最新全局默认并形成自己的持久化模式。A 会话切换模式在一个持久化事务中更新 A 与全局默认；已有 B 保持自己的模式，重开 A 恢复 A。

自动保存触发为停止输入 800 ms、切换内部页签、切换为自动模式。任一触发均走同一个版本检查保存入口；切为手动时停止尚未开始的自动保存。冲突或写入失败不得显示为保存成功。

恢复副本与原文件保存分开。正文、页签变化与阅读位置在使用过程中持久化；只有持久化回执到达才能表示恢复副本已同步，不能依赖宿主短暂 teardown 或内存 widgetState。

恢复时重新核对磁盘版本。脏正文的基线与磁盘不一致时按冲突处理；干净文件读取最新磁盘内容。文件已删除或不能读取时显示具体原因，不静默丢弃脏正文。清空、关闭或放弃编辑后的状态也应持久化，防止重开复活旧页签。

## 评论与主对话契约

每条评论以创建时快照保存以下信息：

| 字段 | 含义 |
| --- | --- |
| commentId | 该条评论稳定且独立的身份 |
| workspaceIdentity、sessionId | 服务端可信绑定的归属 |
| sourcePath、sourceTitle | 完整文件路径与用户可读标题 |
| startLine、endLine | 从 1 开始的起止行号 |
| selectedText | 用户创建评论时实际选中的正文 |
| comment | 用户填写的评论 |
| containsUnsavedEdits | 是否来自未保存正文 |

首次添加评论不隐式保存源文件。继续编辑正文不改写现有评论的选文、行号或未保存标记。

评论通过主输入区上方的聚合上下文胶囊提供给当前主对话，完整数据进入实际提交正文。胶囊内容的文字表示应包含每条评论的完整字段；不能假定 structuredContent 会自动生成原生评论布局。完整明细的可查看方式须在真实宿主中验证。

提交成功指宿主受理，包含正常排队，不要求等待模型回复。失败或被阻止保留本次评论。后续添加不得重新带入已受理的旧评论，也不要求用户额外手动清空。

**并发验收场景**：草稿已有 A → 用户发送 A → 请求尚未返回时添加 B → A 受理 → A 清理、B 仍在草稿 → 再发送时只有 B。失败路径中 A 与 B 都应保留。必须验证模型运行期间准备下一条草稿、排队受理与重新连接后的重复帧处理。

现有同页 updateModelContext 使用固定 context ID。若发送 A 期间把同 ID 内容替换为 A+B，旧请求完成仍按该 ID 删除，新值可能一起消失。不得以禁用追加、固定延迟、定时重发或将并发延后代替用户已确认的行为。

## 工程决定与模块边界

以下为已批准规格采用的工程选择；不是已有运行能力声明。

| 责任 | 位置与边界 |
| --- | --- |
| 编辑页面、目录树、页签、选区评论表单 | 新插件；浏览器文本编辑采用 CodeMirror 6，构建产物随插件本地打包 |
| 文件访问、版本检查与保存 | 新插件服务端；不导入宿主私有编辑器组件 |
| 全局默认、会话状态、恢复副本 | 新插件自有 SQLite，沿用 Node 24 内置 node:sqlite 模式；详见 ADR 0004 |
| ZCode 应用版本与 MCP Apps MIME 判定 | 将既有 artifact-ui 的确实重复判定提取到 common，既有调用方保持行为 |
| 公共包定位与链接 | 复用 common/link.mjs；独立缓存不拼同级路径 |
| 原 Host 连接与必要的只读订阅 | 复用 common；只有接入探针证明需要订阅时才扩展 listen 能力 |
| 批次识别、评论接受状态及清理业务 | 新插件；不得塞进公共网关或复制公共连接实现 |

不新增通用插件框架，不修改研究用宿主快照，不注册辅助会话。构建工具与依赖精确版本在首次实现时核对并锁定，不在未验证规格里猜测版本。

### 服务端公开操作

下列操作由 app-only MCP 工具提供；具体工具名称在实现中统一确定，不向模型公开任意文件或数据库执行入口。

| 操作 | 请求 | 结果与约束 |
| --- | --- | --- |
| 读取绑定上下文 | 不接收任意目标会话 | 当前可信工作区、会话、实际能力状态 |
| 展开目录 | 工作区相对目录 | 当前层目录项，不递归全量扫描 |
| 读取文本 | 工作区相对文件 | 正文、文件元信息、磁盘基线版本 |
| 保存文本 | 文件、正文、基线版本 | 新版本；失败保留编辑，版本不符拒绝覆盖 |
| 读取编辑状态 | 当前绑定归属 | 模式、页签、当前页、阅读位置及恢复正文 |
| 更新编辑状态 | 本次状态变化 | 持久化回执；模式变更事务同时更新全局默认 |

UI 不自填会话身份。不能从“最近会话”或当前选中的外部聊天猜测归属。评论接入操作必须以能力探针结果为准，不预写不存在的宿主接口。

### 持久化数据边界

插件数据位于自己的外置 dataPath，遵循现有原生 `ZCODE_PLUGIN_DATA` 约定。不得写入插件缓存目录、ZCode 会话数据库或 common 网关目录。

数据包括全局默认保存模式与按工作区身份、会话 ID 隔离的编辑状态。会话状态包含模式、页签顺序和临时／固定属性、当前页、各文件阅读位置、脏正文及其磁盘基线。评论关联所需的已受理批次记忆只在接入方案验证后落定，不预设会话分叉继承等额外行为。

## 宿主能力门槛

| 门槛 | 已知事实 | 通过条件 |
| --- | --- | --- |
| H1 独立页面冷启动 | 已有 ui.surfaces 资源入口；既有 demo 曾有初次打开 MCP 连接不可用的边界 | 无模型前置调用地打开侧栏、读取当前工作区文件，关闭重开仍可调用 |
| H2 可信归属 | hostContext 没有会话／工作区字段，UI 调用可带 session_id，workspace_path 未保证 | 真实工具请求核实身份与工作区来源；缺少可信来源时明确阻止文件操作 |
| H3 评论完整接入 | updateModelContext 聚合可用，但无直接发送／删除反向通知且同页 ID 固定 | 完整字段可交给主对话，并实现只清理本次提交、新添评论保留 |
| H4 重启恢复 | widgetState 只保留于 Renderer，面板关闭无法 veto | 独立持久化回执与真实面板回收、重启恢复通过 |

H3 目前尚未通过。自带批次标记并只读匹配权威 queue／userInput 是常规缓存同步候选，不等于证明 Renderer 的并发清理安全。

探针若发现缺口，应记录接口名、实际版本、失败场景和具名能力条件。可以继续 H1/H2 下的文本编辑、保存、恢复；评论实现与首版整体完成保持阻塞。缺少上游能力不自动授权修改 sources 或向上游发票。

## 验证策略

从最高可用入口验证：MCP SDK Client 调用真实服务与临时工作区／数据目录；浏览器测试运行实际构建页面；真实 Desktop 验证原生侧栏和主输入区的连接。

- 文件契约：有效 UTF-8、BOM／CRLF／中文、越界路径、写权限失败、外部版本变化拒绝保存、保存期间新增编辑仍脏。
- 页面契约：目录按需加载、node_modules 可见、剩余宽度居中、临时替换、双击／编辑固定、内部关闭三种结果。
- 状态契约：首次手动；A 更改不改变 B；新 C 继承；重开 A 恢复；脏正文、焦点页与滚动位置恢复。
- 冲突契约：干净刷新、脏正文保留、暂停自动保存，重新读取或保留编辑不静默覆盖。
- 评论契约：快照完整、未保存标记、正常成功／失败／排队、受理后不复活、发送等待期间追加 B 不被 A 清理。
- 确定性并发测试在外部宿主交互边界控制请求返回顺序；不为了测试拆出内部无用接口。
- 真实集成记录启动工作树、安装方式、实际产物路径及 Desktop／CLI 版本。首次长命令落日志与退出码，只消费已有日志，不为补看输出重跑。
- 改可执行行为先见契约测试红灯后实现；本轮纯文档只检查内容、相对链接、依赖图与格式。
