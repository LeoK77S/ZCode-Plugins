# 编辑器状态采用插件自有 SQLite

**状态**：2026-10-12 随规格整体批准的工程选型；尚未实施，不表示用户已验收存储实现。

## 背景

全局默认与当前会话模式需要同时持久化，其他会话必须保持原选择。关闭重开还需恢复页签、脏正文、焦点页面与阅读位置。宿主 widgetState 不能跨重启保证恢复。

本仓库既有 app-mcp 使用 Node 24 的 node:sqlite 和插件外置数据目录。Node 提供文件型数据库、同步连接与 SQL 执行接口，见 [Node 24 官方文档](https://nodejs.org/download/release/v24.8.0/docs/api/sqlite.html)。采用该既有方式可避免自行实现多个状态文件的跨文件事务。

## 规格采用的决定

- 新插件拥有自己的数据库；不写 app-mcp 工件库、宿主会话库或公共网关数据。
- 全局默认与会话编辑状态分开建模；会话状态以可信工作区身份和会话 ID 隔离。
- A 会话修改模式时在一个事务中保存 A 与全局默认，不批量改其他会话。
- 恢复正文、页签与阅读位置作为插件状态持久化；写原文件仍是独立操作。
- 不添加 ORM、通用状态同步框架或与此需求无关的数据库工具。
- schema 有明确版本；不兼容或损坏时报告具体失败，不静默重置用户恢复正文。

## 影响与验证

实现须验证新进程重开、已有会话隔离与多个服务进程读取最新默认。只有事务持久化回执才能确认恢复副本已同步。

数据库表与状态更新接口应保持最小；评论批次存储由接入探针决定，不先做通用事件日志。后续改变时补充 ADR，不把当前规划当作现有运行事实。
