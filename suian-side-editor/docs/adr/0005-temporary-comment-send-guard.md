# 当前采用尽力禁用，完整原生并发评论独立保留

**状态**：2026-10-13 用户已接受当前尽力禁用的发送边界残余风险，并要求创建完整特性票及调整旧票。该决定授权当前实施，不代表接口具备完整安全保证、临时功能已实现或用户已完成产品验收。

## 背景

ADR 0003 要求发送 A 在途时可继续添加 B，受理 A 只清理 A、B 留下。现有插件同页 updateModelContext 固定 context ID，旧发送清理可能删除同 ID 的新聚合值；原 H3 完整并发门槛未通过。

2026-10-13 公开接口调查尚未找到同步 admission pending／Renderer 清理完成信号。queue／userInput 受理事实可先于 Renderer ACK 清理出现；先读取 idle 再更新仍可能与发送交叉。原生模型 running 与发送请求在途是不同阶段。

用户先要求发送在途临时禁用全部评论提交入口并提供 tooltip，再明确接受当前发送边界残余风险，允许按已核公开会话状态实施尽力禁用。此授权不意味着接口缺口已经消失。

## 决定

- #42／46／47／48 按当前调整范围继续推进；不再等待原 H3 完整并发或公开同步／原子状态能力。
- 当前仅用已核实、可信绑定当前会话的公开状态尽力禁用全部添加／提交评论入口，包括已打开表单的提交；保留选区与未提交评论正文。
- tooltip 说明降低新增评论被本次发送清理风险的原因、实际观测状态与恢复条件，不把无法取得的精确 pending 当作已观测事实。
- 若用模型 running 作保守代理，明确可能整个回复期间锁定，不能称为 admission pending。状态允许时恢复；未知／断连如实显示，不当空闲。
- 正常／失败／排队受理、精确批次缓存消费、完整快照、未保存标记、可信归属与隔离仍须验收，不以模型结束猜受理，不要求用户手动清空，不增加插件内聊天或辅助会话。
- 完整原生并发独立进入 [SE-11](../issues/11-native-concurrent-comment-feature.md)，仍要求同步 pending／消费批次或等价公开保证、A 在途追加 B、A 受理只清理 A、失败保留 A/B、重连与晚到回执安全。能力具备并验证后移除临时禁用。

## 已接受风险与完成边界

**当前方案只提供尽力保护**：状态可能迟到，idle 读取后发送有竞态，queue／userInput 受理后恢复可能早于 Renderer 清理。采用 running 保守代理则可能整个模型回复期间禁用。用户已接受发送边界残余风险，实施与证据须如实保留它，不声称消除竞态。

当前完成要求实际公开接口、全部入口禁用、tooltip、草稿保留、恢复、正常／失败／排队及缓存闭环通过；风险授权不代替实现验证。SE-11 独立保持未完成，当前票通过不自动关闭完整特性。

## 文档与工程影响

本决定仅替代 ADR 0003 对“首版必须在途追加、不得禁用或独立延后”的当前实施限制，评论快照与主对话行为继续有效。ADR 0003、原调查和所有冻结验证文档／JSON 保留原时点，不回写新结论。

当前规格、票索引及 #42／46／47／48 的验收范围同步调整。SE-11 已由根代理创建为 [#57](https://github.com/ONEGAYI/ZCode-Plugins/issues/57)，保持 open、enhancement／wait-for-upstreaming；旧票标签与状态不因文档拆分改变。远端票附完整正文，不能只依赖尚未推送的本地文档。

不修改 sources、真实用户 profile 或正常会话。功能实施仍遵循契约测试先行，长流程首次落盘日志与退出码，验证限于已授权隔离范围；推送、发布与正式合并另按根规则和会话授权处理。
