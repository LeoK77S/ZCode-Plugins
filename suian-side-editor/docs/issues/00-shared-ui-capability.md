## 问题与交付

新编辑器需要沿用现有 Desktop 应用版本与 MCP Apps MIME 判定。复制 artifact-ui 的基础判定会形成两份维护入口。

把已经存在且两个调用方确实需要的版本／MIME 判定提取到公共包，通过稳定 link.mjs 入口使用。保留现有工件资源启用和工具可见性的行为，不建立通用 UI 框架。

## 责任范围

suian-zcode-common 的小型能力判定入口；suian-zcode-app-mcp/artifact-ui.mjs 的调用接入及相关测试。此票不增加编辑器业务。

这是必要且独立的准备性重构；新插件功能在 SE-01 开始，避免把重构与业务行为混在一起。

## 验收条件

- [ ] 先以既有工件 UI 的客户端初始化与资源枚举测试固定行为，再迁移公共判定；迁移后原测试保持通过。
- [ ] Desktop 传入应用版本优先；CLI 0.16.9 不被误当成 Desktop 版本。
- [ ] 未知／过低应用版本、非 ZCode 客户端或缺少 MIME 能力时，行为与迁移前一致。
- [ ] 公共层不导入业务插件；独立缓存安装可通过已有稳定包链接定位公共实现。
- [ ] 本票不改工件正文、工具数量、宿主设置或发布版本。

## 验证与完成证据

在 MCP SDK Client 高层入口跑原 artifact-ui 测试与公共判定契约。只消费第一次测试日志和退出码。

可执行行为遵循契约测试先行。首次长命令落盘记录日志和退出码；只汇总脱敏证据。通过依赖票还必须满足该票声明的实际能力条件；调查结束本身不会解除能力阻塞。
