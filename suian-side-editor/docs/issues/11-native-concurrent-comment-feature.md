## 问题与目标

原生评论有各自独立 ID。发送 A 时捕获本次附件，发送请求在途期间仍可添加 B；A 受理只清理 A，B 留给下一条消息。插件同页 updateModelContext 当前使用固定 context ID，发送期间替换为 A+B 可能让旧请求按同 ID 清除 B。只读受理匹配能够辅助缓存同步，不能自动给出 Renderer 清理的原子保证。

2026-10-13 用户明确接受当前尽力禁用可能存在的发送边界残余风险，完整体验仍需与原生一致。本票将它保留为独立特性：发送请求在途时继续评论，精确清理本次受理批次，失败保留所有待发评论，重连和晚到回执安全；能力验证完成后移除临时禁用。

发送请求在途（admission pending）是发送尚未得到受理或明确失败的阶段，不是模型正在生成回复的 running。模型运行期间准备后续草稿、正常排队受理，以及 A 在途时追加 B 是不同场景，必须分别验证。

## 必须保留的评论与隔离契约

- 从实际 CodeMirror 选区形成创建时固定快照，每条具有稳定独立 commentId。
- 完整快照包括可信 workspaceIdentity／sessionId、完整 sourcePath／sourceTitle、1-based startLine／endLine、selectedText、comment 和 containsUnsavedEdits；继续编辑、保存或外部修改不改写旧快照。
- 可评论未保存正文，并有明确未保存标记；添加评论不隐式保存源文件。
- 评论进入当前主对话输入区上方聚合胶囊，实际提交正文包含全部字段，明细可查看；不插入可见输入文本、不新建辅助会话、不增加插件内聊天或模型回复。
- 正常受理包含排队受理，不等待模型完成；失败或被阻止保留，不要求手动清空，后续评论不复活已受理旧评论。
- 所有状态、评论与批次绑定可信当前会话／工作区，不使用最近会话或 UI 自填身份，不跨归属清理。
- 源文件写回与恢复副本回执仍分开；不修改 sources、真实用户 profile 或正常会话。

## 宿主公开能力需求

**当前缺口仍存在**：2026-10-13 接口调查未找到公开 SDK 的同步 admission pending／Renderer 清理完成信号。queue／userInput 可先于 Renderer ACK 清理出现，不能独立作为恢复条件；读取 idle 后再发送存在竞态，轮询不能把它变成原子条件。

本票收纳以下能力需求，实际接口名和版本以宿主支持或验证结果为准，不预设不存在的 API：

1. **在途状态与安全完成边界**：提供可信会话关联的发送开始、受理／明确失败及清理完成信息；状态必须与评论更新的允许时点同步或原子关联，避免“读取空闲 → 发送开始 → 仍更新同 ID”的竞态。首次连接、断连、重连和晚到状态有明确语义。当前尽力禁用暂不要求这项能力通过；本票仍严格要求它或等价公开保证，以消除已接受的过渡风险。
2. **独立身份与精确批次**：允许每条评论独立关联发送捕获的批次／修订，或提供等价公开能力；受理与清理只能作用于捕获的评论，不删除同页后续追加内容。
3. **可关联受理与清理结果**：正常、排队、失败／阻止能关联本次批次和实际清理结果；重复帧、重连快照、晚到回执不复活旧评论、不误清新评论。
4. **真实可控验证入口**：能在外部交互边界控制发送 admission 的开始与结果，证明 A 在途追加 B 的场景真实发生；模型 completion 暂停只能证明模型阶段，不替代该条件。

这些是待满足的契约，不宣称当前宿主已提供。若完整独立附件／修订清理通路提供等价保证，可按实际公开事实收窄所需接口，不要求为临时方案永久保留额外门禁。
