# SE-06 · 将完整的选区评论快照加入当前主对话胶囊

**状态**：已发布，尚未实施；依赖与实际能力条件未满足前保持阻塞。

**GitHub**：[#46](https://github.com/ONEGAYI/ZCode-Plugins/issues/46)。

**Blocked by**：[#42 · SE-02](https://github.com/ONEGAYI/ZCode-Plugins/issues/42)、[#43 · SE-03](https://github.com/ONEGAYI/ZCode-Plugins/issues/43)。

规格：[首版规格](../text-editor-spec.md)。顺序：[票索引](../text-editor-tickets.md)。本地标识不是 GitHub Issue 编号。

## 问题与交付

编辑正文可能未保存或继续变化，模型需要创建时的准确选文与文件位置；评论应由主对话使用。

选择文本并填写评论后，将完整快照加入当前主输入区上方的聚合胶囊；模型回复始终在主对话。

## 责任范围

suian-side-editor 的选区评论表单、快照数据和主对话适配；采用 SE-02 已验证接入，不猜宿主接口。

发送受理后的缓存清理、失败与并发场景由 SE-07 完成；本票通过不代表首版评论闭环完成。

## 验收条件

- [ ] 评论保存稳定独立 ID、可信工作区／会话、完整路径／标题、1-based 起止行号、实际选文与评论。
- [ ] 未保存正文允许评论，明确标记包含未保存编辑；添加评论不隐式保存源文件。
- [ ] 继续编辑、保存或外部修改不改写已创建评论的选文、行号和未保存标记。
- [ ] 多条评论聚合提供，每条完整信息进入提交正文；胶囊摘要简短不得导致实际字段丢失。
- [ ] 完整明细的可查看形式按 SE-02 实际宿主能力验收，不假定 structuredContent 自动渲染原生布局。
- [ ] 评论只进入当前绑定主对话，不插入可见输入文本、不新建辅助会话、不在插件接收模型回复。
- [ ] 测试通过真实编辑器选区及外部主对话适配边界，不只测试一个序列化函数。

## 验证与完成证据

实际构建页面创建评论快照；MCP/适配边界验证归属与完整提交正文；Desktop 验证主输入区胶囊。

可执行行为遵循契约测试先行。首次长命令落盘记录日志和退出码；只汇总脱敏证据。通过依赖票还必须满足该票声明的实际能力条件；调查结束本身不会解除能力阻塞。
