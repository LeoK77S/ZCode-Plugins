## 问题与交付

宿主页面会被关闭或回收，widgetState 只存在 Renderer 内存；只在 teardown 保存不能满足重开和应用重启恢复。

使用插件自己的外置数据目录与 SQLite，在编辑和界面状态变化过程中保存恢复副本。新进程和重新打开页面恢复当前会话状态，重新核对磁盘后应用正文。

## 责任范围

suian-side-editor 的会话恢复状态、持久化回执和页面恢复；不扩展宿主生命周期。

不实现会话分叉继承、跨设备同步或无限历史版本；恢复对象以规格列明状态为准。

## 验收条件

- [ ] 恢复页签顺序、临时／固定属性、当前文件页、各文件阅读位置和未保存正文。
- [ ] 保存恢复副本与写源文件有独立状态；回执前不能表示副本已持久化，失败明确显示。
- [ ] 关闭内部页签、放弃修改或切换当前页后的新状态持久化，重开不复活被关闭的旧页面。
- [ ] 干净文件重开读取最新磁盘；脏正文基线过期时保留恢复内容并显示冲突、暂停自动保存。
- [ ] 文件删除或无法读取时报告原因，不静默丢弃对应脏正文。
- [ ] 实际验证原生面板关闭、离屏页面回收与应用重启，不依赖页面阻止关闭或超过宿主 teardown 时间。
- [ ] 会话与工作区隔离，新数据库进程读取结果与旧页面一致。
- [ ] 恢复当前文件页不擅自抢走主对话输入框键盘焦点。

## 验证与完成证据

真实状态库的新进程测试、实际构建页的阅读位置恢复测试、隔离 Desktop 三种生命周期验收。
