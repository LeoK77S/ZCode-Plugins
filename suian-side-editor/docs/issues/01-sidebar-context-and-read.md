**状态**：只读开发切片已在本地实施并通过公开 MCP/stdio 与浏览器夹具检查；真实 Desktop 的 H1/H2 尚未验证，本票仍未完成。详见 [验证记录](../se01-verification.md)。

## 问题与交付

页面不能从 hostContext 直接获取会话和工作区，既有工件 demo 还曾出现初次打开 MCP 连接不可用。先验证编辑器可独立进入且不会读错工作区。

建立 session 可用的独立原生侧栏与本地资源。工具从实际请求和已核实启动环境确定当前会话／工作区，页面通过 app-only 工具读取一份已有 UTF-8 文本并显示；无需先调用模型工具或发送主对话消息。

## 责任范围

suian-side-editor 的原生元信息、stdio 入口、UI 资源与只读文件工具；common 只使用已有包定位／能力判定。

本票只读正文，不引入多文件编辑、保存、评论或正式市场发布。

## 验收条件

- [ ] 记录启动工作树、安装方式、实际资源／入口路径、Desktop 与 CLI 版本。
- [ ] 在新测试会话第一次打开侧栏即可调用只读工具；关闭重开、切换两个不同工作区仍绑定各自正确归属。
- [x] 公开 MCP 契约：工具按启动绑定和请求 meta 返回归属，不接受页面随意填写目标会话；真实 UI meta 来源仍待 H2 验证。
- [x] 公开 MCP 契约：缺少可信工作区／会话来源时明确报告并阻止文件访问，不猜最近会话。
- [x] 文件契约：静态相对路径解析后的真实目标在工作区内；穿越、外部链接和任意绝对路径不能越界。
- [x] 文件与浏览器夹具契约：有效 UTF-8 正常显示；非法编码、二进制、缺失文件和真实 Windows 权限拒绝明确报错。
- [ ] H1/H2 未通过时记录具名能力缺口并保留后续文件操作的阻塞，不能仅关闭调研票就宣称可用。

## 验证与完成证据

MCP Client + 临时工作区验证读取边界；真实隔离 Desktop 验证冷启动和请求元数据，不改用户原工作区文件。

可执行行为遵循契约测试先行。首次长命令落盘记录日志和退出码；只汇总脱敏证据。通过依赖票还必须满足该票声明的实际能力条件；调查结束本身不会解除能力阻塞。
