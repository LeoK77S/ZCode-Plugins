## 问题与交付

插件同页 updateModelContext 使用固定 context ID。A 发送等待期间若把同 ID 替换为 A+B，旧发送受理后的清理可能把 B 一起删除。完整原生体验仍需独立身份与精确批次清理，交由 SE-11 验收。

当前交付按已核实且可信绑定当前会话的公开状态尽力禁用所有评论提交入口，并通过 tooltip 说明原因、实际观测状态和恢复条件。用户已明确接受发送边界残余风险：状态可能迟到，queue／userInput 受理事实可能先于 Renderer ACK 清理；读取 idle 后再发送也存在竞态。因此不再将同步／原子状态能力作为当前实施的硬阻塞，也不声称临时禁用消除了竞态。

发送请求在途（admission pending）是尚未收到受理或明确失败的发送阶段，与模型正在生成回复的 running 不同。若采用 running 作为保守代理，必须说明可能在整个模型回复期间禁用评论，不能声称它等于在途；排队受理事实仍不等待模型结束。

## 历史事实与当前接口条件

原探针见 [SE-02 验证](../se02-verification.md) 和 [证据 JSON](../se02-evidence.json)。这些文档与 JSON 保留原时点，不为范围调整改写成功、失败或未验项。

- 已证明诊断胶囊 tooltip 展示完整字段，完整路径、标题、行号、选文、评论和未保存标记进入真实当前 userInput；诊断夹具不替代实际编辑器选区业务。
- 已观察到普通受理清理、单批发送失败保留和模型 running 期间的排队受理；模型 completion 被暂停不是发送 admission 被暂停。
- 已记录同页固定 ID 缺 revision、缺关联消费通知、未找到公开可控 admission hold/release 的缺口；普通 update Promise 只表示设置完成。
- 原 A/B 在途并发、失败保留 A/B、重连及精确缓存消费未通过；不能移用部分探针成功勾选当前实现条件。
- 2026-10-13 接口调查尚未找到公开 SDK 的同步 admission pending／Renderer 清理完成信号。queue／userInput 的受理事实可先于 Renderer ACK 清理出现，不能作为无竞态恢复的证明；读取 idle 后再发送仍有竞态，盲轮询不能补齐。

**最新授权调整**：用户已接受上述残余风险，当前临时方案可按已核公开会话状态尽力禁用，不再等待同步／原子在途与完成信号。接口缺口仍是事实；完整同步 pending、消费批次及原生并发保证保留于 SE-11，不能凭空声明宿主已有。
