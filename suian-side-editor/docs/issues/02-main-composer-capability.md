## 问题与交付

原生每条附件有独立 ID；插件同页 updateModelContext 是固定 ID。旧发送的成功清理可能删除发送等待期间的新聚合值。

用实际受支持接口证明完整评论可以进入主对话，并可靠区分本次受理的评论与新追加评论。确定后续可用的接入方式、回执／批次对应关系和版本门槛；不把只读订阅观察到正文等同于 Renderer 清理原子性。

## 责任范围

suian-side-editor 的隔离接入探针和证据；确需原 Host 只读订阅时，负责 common/gateway-client.mjs 的窄接口及兼容契约。sources 保持只读。

本票是能力门槛，不是普通功能验收。得出缺口并完成调查不等于 H3 满足；基础文本路径仍可继续。

## 验收条件

- [x] 胶囊 tooltip 显示完整诊断字段；完整路径、标题、行号、选文、评论和未保存标记进入真实当前 userInput。诊断数据不替代正式选区评论业务。
- [ ] 可控验证 A 已加入 → 发送 A 等待响应 → 加 B → A 受理 → 只清理 A、B 保留，且第二次发送不再包含 A。
- [ ] 发送失败时 A/B 保留；排队受理也能确认提交，不等待模型结束。
- [x] 记录主输入区删除／发送清理未向此页面提供关联消费通知；update Promise 仅表示设置完成，无法据此保证插件缓存不复活已受理评论。
- [ ] 若采用 structuredContent 批次与只读 queue/userInput 订阅，证明批次精确匹配、会话隔离、重复帧幂等，并另外证明并发清理安全。
- [x] 使用既有公共 call 和只读快照已完成当前探针；未扩展 common 订阅或改变公共行为。
- [x] 记录固定 ID 无 revision、缺关联消费回执及未找到公开 admission hold/release 三项缺口；保留真实首次 FK 发送失败和正常 Native 夹具修正，SE-06、SE-07、SE-08 的 H3 条件继续阻塞。
- [ ] 不以禁用追加、固定延迟、定时重发、手动清空或改宿主私有 DOM 作为通过；不修改 sources，不未经授权向上游发票。

## 验证与完成证据

外部宿主交互边界的确定性场景加真实隔离 Desktop 证据。只读探针优先；需实际发送时只使用为验收创建的测试会话，并按届时授权范围执行。

可执行行为遵循契约测试先行。首次长命令落盘记录日志和退出码；只汇总脱敏证据。通过依赖票还必须满足该票声明的实际能力条件；调查结束本身不会解除能力阻塞。

Native 排队受理在模型 completion 尚被合成 Provider 暂停时已观察到；这不是 admission 暂停。A 发送失败后胶囊／输入保留，A/B 同时处于未返回失败路径仍未可控验证，因此第三项不因部分成功而勾选。重连重复帧和精确缓存消费未实施；没有循环竞态重试或通过私有宿主补丁补作门槛。
