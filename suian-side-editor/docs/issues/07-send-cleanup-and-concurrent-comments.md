## 问题与交付

宿主清空胶囊不等于插件缓存同步；固定 ID 的整批替换又可能让旧发送删除等待期间新增内容。当前先以已核公开会话状态尽力禁用评论提交、保留未提交草稿，并精确清理已受理缓存。状态可能迟到，受理事实可能先于 Renderer 清理，解除禁用后仍可能存在发送边界竞态；用户已明确接受这一过渡风险。

正常受理后清理本次评论，失败或被阻止保留，排队受理也确认提交。后续添加不得复活已受理评论，不要求用户手动清空。按实际公开状态尽力禁用全部添加／提交入口，保留选区和未提交表单正文；根据实际状态恢复。若采用模型 running 作保守代理，可能整个回复期间禁用，不能声称它等于 admission pending。

完整体验仍要求 A 发送未返回时可添加 B，A 受理只清理 A、B 留下；A 失败则 A/B 保留。它由 SE-11 独立验收，未来移除临时禁用。本票通过不代表完整原生并发已经实现。

本票仍是当前交付的必验项；基础编辑器可用不能替代发送、失败、排队及缓存清理闭环。

## 验收条件

- [ ] A 正常受理后从主草稿与插件待发缓存移除；恢复后添加 B 不重新带入 A，第二次提交正文只有 B。
- [ ] 被阻止或发送明确失败时 A 保留，可正常重试；不能按时间或模型状态推断成功。
- [ ] 排队受理依据明确回执／权威队列及精确批次确认，不等待模型回复或队列出队。
- [ ] 已核实可信当前会话的公开状态驱动所有添加／提交评论入口尽力禁用，包括已打开表单提交；明确实际信号、迟到和恢复边界，不声称覆盖原子发送／清理窗口。
- [ ] 禁用保留选区和未提交评论正文，tooltip 可查看并说明降低新增评论被本次发送清理风险的原因、实际观测状态及恢复条件。
- [ ] 依据实际公开状态恢复；模型 running 与请求在途区分，若保守代理导致整个回复期间禁用须明示。queue／userInput 受理后恢复可能早于 Renderer 清理，不隐藏用户已接受的残余风险。
- [ ] 状态未知／断连如实显示，不当空闲；重新连接及晚到状态按公开语义处理，不假装拥有同步清理信号。
- [ ] 插件自身缓存消费对重复帧、重连快照和晚到旧回执按独立评论身份／精确批次幂等处理；已受理 A 不复活，恢复后新加 B 不被旧缓存回执清除，不串会话或工作区。宿主 Renderer 发送边界的残余风险另行记录，不假称已消除。
- [ ] 外部宿主边界测试验证实际状态、结果与缓存行为，未可控 admission 的部分如实列为未证明；真实隔离 Desktop 覆盖正常／失败／排队、在途禁用、内容保留及恢复后新评论。
- [ ] 不使用固定延迟、盲轮询、循环重发、手动清空、猜测事件、私有 DOM 或修改 sources 代替保护；queue／userInput 受理可能先于 Renderer ACK 清理，读取 idle 后发送也有竞态；仅以实际公开状态尽力处理，残余风险已获授权，但不能声称无竞态。
- [ ] 完整在途追加由 SE-11 单独保持未完成；本票当前完成不要求 A 在途添加 B，也不删除该未来要求。
