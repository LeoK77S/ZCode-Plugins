实现只清理本次已受理评论的主对话发送语义，覆盖正常受理、失败、排队、并发新增与重新连接，不增加用户必须手动清空的步骤。

## 验收条件

- [ ] 评论 A 正常受理后从主草稿与插件待发缓存移除；随后添加 B 不重新带入 A。
- [ ] 被阻止或发送失败时 A 保留，可正常重试；不能按时间或模型状态推断成功。
- [ ] 排队受理按明确回执／权威队列确认，不等待模型回复或队列出队。
- [ ] A 发送请求等待响应时添加 B；A 成功只清理 A，B 留给下一条消息；第二次提交正文只有 B。
- [ ] A 发送失败且期间加入 B 时，两者都保留；模型运行期间仍可准备后续评论。
- [ ] 重复帧、重连快照和晚到的 A 回执不复活 A、不清除 B，处理以独立身份／精确提交批次为准。
- [ ] 确定性测试控制外部返回顺序，证明竞态确实发生；真实隔离 Desktop 重现同一流程。
- [ ] 不用禁用新增、固定延迟、循环重发、手动清空或未验证的私有事件代替通过；能力不足时保持阻塞。
