# SE-05 恢复副本本地验证

本地实现从统一基线 `adb7e93ab178380cc4c9c433f6b4ea20f6d490fc` 开始。范围为 [SE-05](issues/05-durable-editor-recovery.md) 的状态库、恢复界面与公开契约；H4 三类 Native 验收及独立两轴由根安排。此记录不代表整票、完整首版或用户验收通过。

## 已实现的边界

新增 app-only `get_editor_state` 与 `update_editor_state`，仍由启动工作区与宿主 session meta 绑定归属。请求只包含恢复快照，不能指定目标身份；状态路径须为工作区相对路径。源文件读写继续使用原文件工具，没有任意数据库执行入口。

自有 `editor-state.sqlite` 的 schema 2 增加 `session_recovery`，与模式表使用同一数据库、独立事务。schema 1 在写事务内无损迁移；未知版本、损坏的 JSON 或无效恢复记录明确报错，不清库。副本提交成功只确认副本，不写源文件或修改保存模式。

副本只保存页签顺序、临时／固定属性、当前页、各文件像素阅读位置，以及脏正文的内容、原正文、编码特征和磁盘基线。干净正文不存副本；恢复读取最新磁盘。CodeMirror 对象、资源 URI、订阅、计时器、单调时钟和键盘焦点不入库。恢复通过原受审读取工具取得新的资源关联，再正常订阅。

正文与可恢复界面状态改变时，200 ms 合并提交最新快照；有在途提交时串行保留随后变化。页面立即显示待同步，回执只确认该快照；旧回执不确认更新的正文。失败明确显示且可重试。页面关闭前仍显示待同步的变化不保证已落盘；验收关闭／重启必须先观察副本成功回执，不依靠 teardown 延长宿主寿命。

恢复遇过期磁盘基线、删除或读取失败时，保留脏正文并提示原因、暂停自动保存。干净但不可读的页签保留错误且不可编辑，避免制造未经读取的正文基线。重新读取需使用已有放弃确认。恢复当前页不调用 focus，不恢复光标或选区；跨主输入框的实际焦点由 Native 验收确认。

## 契约与回归

- 基线 SDK 33/33。新增恢复契约 4 项：schema 1 无损迁移及新 stdio 进程／工作区会话隔离；app-only 输入边界；真实 SQLite 失败回滚与重试；损坏记录明确拒绝且保留。最终 SDK 合计 37 项，结果由 JSON 索引列明。
- 原浏览器 42 项／组继续执行；新增 6 项实际构建页契约：完整恢复及焦点；过期／删除与确认重读；迟到 ACK 和真实 SQLite 失败；切页滚动／固定／关闭放弃后的重建；真实 Windows ACL 拒读后恢复；初始化失败保护旧副本及重试。最终合计 48 项／组。
- 仍通过唯一 `build-ui.mjs` 构建本地 HTML；第三方 11 份许可保持嵌入。语法检查按既有 `check` 脚本执行；项目无另设 linter。未改其他插件与 common，不扩大回归到无影响模块。

## 首次失败与修正

首次恢复数据库契约在未注册 `get_editor_state` 的基线上失败；新增工具与 schema 迁移后通过。第一次页面测试的种子编码漏核对已有 `name: utf-8` 字段，严格输入边界拒绝了种子；修正测试编码后，实际旧构建页面因没有恢复页签超时，随后最小页面实现通过。两次失败各自保留，不把种子错误当作产品红灯。

新增损坏恢复记录契约实际红灯为返回无效记录而非明确错误；补存储边界校验后通过，原记录保留。

滚动测试首次在 CodeMirror 初始测量完成前设置 760 像素，随后实际位置变为 1364；未归因于副本写入错误。测试改为明确等两次动画帧，先核对页面实际到达 760，再切页、核对数据库和重建恢复。另一次 ACL 测试匹配了不存在的“权限不足”文案，改为读取工具实际文案后通过。产品断言没有降低，失败日志不覆盖。

首次最终全量浏览器执行中，新恢复 6 项全部通过，原资源复核的一项 setup 在异步读回创建页签前调用 `getComputedStyle(null)`。仅增加等待具名页签可见，再保留原正体与后续重绑定断言；不采用自动重试，也不将此 setup 异常判为产品重绑定失败。修正后的完整首次结果另存日志。
