**四项 P2 均先由公开契约复现，再作最小修正**。本轮从 Source `784b3c5341f81aa1dc349acdf99e2efaaaf24704` 追加；复核固定整合范围结束于 `62490ff`。资源重绑定由两轴重复发现，只计一项，但两种触发各自验证。最终 SDK 33/33、浏览器 38 项／组通过。新提交仍待独立两轴和 Native 验收，不能据此放行 #44、#45 或 H3/H4。

## 发现、实际红灯与修正

| 发现归属 | 公开契约的实际红灯 | 修正后的行为 |
| --- | --- | --- |
| 两轴：重绑定，首次订阅暂时失败 | 用户确认重读成功，仍仅一次 `resources/subscribe`，预期两次，`1 !== 2` | 确认重读后按需重新订阅，随后真实外改正常同步 |
| 两轴：重绑定，工作区内目录换指 | 旧资源实际拒绝 `registered_path_changed`；受审重读返回新路径／URI，页面新路径页签数仍为零，`0 !== 1` | 接受受审工具的新规范路径／URI，更新页签和面包屑，退订旧关联并订阅新关联；新目标后续外改正常同步 |
| 规范轴：保存掩盖同步失败 | 原文件手动保存成功后状态仅“已保存”，没有尚未恢复的订阅失败 | 独立保留同步失败状态，显示原文件保存成功与同步失败；自动写回继续暂停，确认重读恢复后才继续 |
| 规范轴：后台通知发送拒绝 | 真实 `transport.send` 拒绝资源通知，Node 记录未处理拒绝；连接关闭与在途发送拒绝交错也复现 | 后台任务捕获拒绝，在 stderr 明确报告关联 URI 和失败，结束该资源监测；关闭后不再排程，无通用重试或隐式回退 |
| 规格轴：同版本重读后的旧错误 | 真实 ACL 拒读产生错误资源回执；拒写后恢复 ACL，重读成功仍 V0；旧错误迟到后不再核对当前资源，`false !== true` | 成功保存／受审重读推进操作顺序；较早资源结果即使内容版本相同也失效，操作结束核对当前资源，自动写回可以继续 |

UI 测试运行服务实际返回的构建 HTML，所有文件工具与资源请求经过真实 MCP SDK／InMemoryTransport。只有通知发送故障、订阅首次故障及回执延迟在公开桥接边界控制；不伪造正文版本、权限错误或磁盘保存回执。Windows ACL 仅作用于自有临时文件，finally 恢复。

后台发送失败的两项 SDK 契约使用隔离子进程，公开 `transport.send` 真实拒绝。子进程记录未处理拒绝和 stderr，并在后一轮真实文件变化后确认未重试。这里验证服务端报告与任务结束，不声称页面收到新的通知失败事件；公开通路没有新增这种事件。

## 首次失败与历史保护

新日志、退出码、产物快照及截图统一归本轮独立证据目录，由新的转移清单定位。以下驱动器错误保留原始日志，未归为产品失败：

- `rebinding-save-red.log` 的目录项第一次用了错误的中文正则。纠正为实际“真实路径已改变”后，`rebinding-acl-red.log` 命中新路径页签断言。
- `send-failure-red.log` 的首次子进程遗漏 Desktop 版本，文件工具未启用，读取结果没有 `structuredContent`。补齐夹具版本后，`send-failure-red-2.log` 命中实际未处理拒绝。
- `history-before.log` 第一次冻结脚本用了错误的许可文件名。纠正为 `THIRD-PARTY-LICENSES.txt` 后，`history-before-2.log` 完成 90 文件字节／SHA 核对与旧产物冻结；此时尚未构建新资源。

旧 784 转移清单的 90 文件及其清单 SHA `a2c54d2d…` 在本轮前后均核对不变。旧 HTML 318324 字节／`067f3552…` 与 12465 字节许可已先冻结，再构建新资源。浏览器回归首次遗漏截图目录变量，在自有默认目录新建两张截图；核对创建时间与本轮一致后，将文件移到本轮截图目录，没有覆盖旧清单中的截图，也未为截图重跑回归。

原 Native 的 ID7 读取成功，ID8–12 稳定文件检查每次允许后再次审批，ID13 拒绝后暂停，这次失败没有改写。根冻结的 278 项 Native 证据和其他工作树的历史不归本轮修改；本轮未操作 Native、GUI/CDP、宿主权限、公共层、模式数据库语义或正式缓存。
