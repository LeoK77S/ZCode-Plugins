## 整合驱动失败与修正

上一轮 Source 浏览器 41 项当次通过；根整合首跑实际为 40/41。唯一失败在 `browser-resource-review.mjs:49`：先通过 RPC 采样 `Date.now()`，再用后续 RPC 暂停到该时刻，期间时钟已经推进。失败发生在打开文件和产品断言之前，属于驱动竞态。根保留 `.scratch/integration-se04-watch-round2/browser.log`／`.exit`；本轮没有用重跑覆盖这次失败。

六个现有时钟夹具使用相同采样方式，第二轮的 100ms 缓冲也没有消除竞态。本轮各修改两处：导航前安装已知起始时间，初始化完成后暂停到固定的较晚测试时间。采用本机 Playwright Clock 官方文档提供的初始化顺序，未加重试或降低断言。800ms 等行为均在暂停后编辑并用 `runFor` 计量，不把初始化的时间推进作为用户编辑等待。

## 规范轴实际红灯与最小修正

真实固定页顺序为 `[A,C,B]`。首次设置回执等待时先编辑 C；100ms 后切回 A，再收到继承 Auto 的真实数据库回执，C 原有计时应继续等待剩余700ms。工作区内目录 A 改指已打开目标 B，用户确认重读 A 时，旧实现先移除 A、激活相邻 C，再激活 B。中间切页对 C 发起自动写回。

`red.log` 在公开 `tools/call save_editor_text` 边界实际记录 C 已保存调用一次，预期零次，`1 !== 0`。反馈约 1.11 秒，没有夹具失败。目录链接、设置回执、文件字节、工具及资源均经过真实 MCP／SDK，自有临时工作区没有伪造保存版本。

修正仅让已有 `removeFile` 接受明确下一页，重绑定直接激活实际目标 B，普通关闭仍按邻页规则选择。没有瞬时激活 C、引用计数、重试或新状态框架。`green.log` 一项通过：C 的799ms仍不写回，800ms才写回；B 的脏正文和原订阅保留，最终两文件磁盘内容正确。
