## 三种生命周期

| 实际路径 | 观察与结果 |
| --- | --- |
| 关闭后立即重开 | 同一 guest 保留，页签顺序、当前页、可见正文及阅读位置匹配；关闭前最新副本写回已获 ACK。此组不证明 guest 被销毁 |
| 自然离屏回收 | 同一次正常关闭约五分钟后，标准 browser target 销毁事件与 Main 中对应 webview 消失均被观察到；新 guest 的实际 `ui/initialize`、状态读取及三次文件受审读取均获 ACK，完整恢复快照匹配 |
| 应用正常退出后重启 | 正常窗口关闭后旧应用自然退出，code 0、signal null、未强制终止；新鲜归属核验中旧实例所属进程剩余 0。新应用沿用同一自有 profile，新 guest 实际初始化及恢复成功；八项 HKCU 前后类型／内容完全相同 |

自然回收使用普通 Target 事件和 DOM 观察，没有调用私有销毁接口、强制回收或改计时器。初次公开快照 RPC 超时后，在同一次离屏周期补用纯被动 CDP 观察；没有重新关闭面板来重置计时。应用重启组使用真正的新应用进程，不把先前接入准备时的 GUI 启动当作 H4。

## 首次失败与保留边界

- 首轮 App 连接摘要不可用发生在编辑器 guest 创建前，接入失败 142 项加连接补查 3 项另冻。只读公开入口研究没有找到可定向既有 Desktop 会话的重连入口；未将设置页状态当作会话连接证明，也未判定租约丢失根因。
- 原生任务选择歧义发生在触发编辑器前。第一阶段 ID2/3 因审批观测适配器准备延误超过本地等待时间，ID24 因新请求未被短观测覆盖而超时；公开重试随后成功。三次超时不归于用户未点击，也不改记为服务错误或产品阻断。ID24 与截图相邻的因果机制未证实。
- guest 标准截图被顶层目标限制拒绝，首个自然回收观察的公开快照 RPC 超时；原日志与后续普通 viewport／纯被动观察分别保留。
- 重启准备助手首次要求快照 DTO 的 `meta.workspacePath` 与公开调用路径字符串相同，实际 DTO 保留反斜杠，断言超出了公开契约。公开 Host 路径、调用范围和原生精确任务键均保持一致；未声称 DTO 字段语义等同公开路径，亦未用 `resolve` 推断同一归属。

根已按字节及 SHA-256 迁移五组冻结证据：第一阶段 171 项、补充 33 项、布局 5 项、正常退出 13 项、最终重启恢复 89 项。最终 89 包含原 85 不变及新增 4 项，不能计为 85 加 89。首轮接入失败、首命令日志、连接研究及进程／控制器观察另保留；索引中的忽略目录和原始材料仅在本机，manifest 的相对条目／字节／哈希格式可复用，不保证随仓库分发。
