# SE-05 首轮复核修正

范围为初版 `7c6c6e59788bc108268dce063f7dfc360212b77f` 之后的三项恢复 P2。初轮规范轴报告规范目标合流、恢复重入两项；规格轴同时确认合流，并报告初始化交互丢副本。以下为实现者的实际红绿，独立窄复核及原生 H4 仍待根安排；不表示整票或用户验收通过。

## 规范目标合流与旧脏身份

原副本保存两页，面板关闭期间把第一目录改指第二目录。三个实际构建分支均在基线上出现两个同规范目标页签，预期一个；服务端受审读取返回同一路径和资源关联。

干净恢复页现在复用规范目标，保留固定属性及当前页映射，合流后的快照另取持久化回执。改指的旧脏副本保留原身份与完整正文，显示路径变化，暂停写回并不绑定新目标资源。它与新目标自己的脏正文分别保留，必须明确重新读取或放弃旧副本，才消除旧身份。

这项暂停覆盖保存按钮、正文焦点下的 Ctrl+S 及自动保存。新旧目标恰同字节基线的分支也没有发出保存请求；不能依靠字节版本碰巧不同兜底。明确放弃旧身份后，新目标脏正文及副本仍完整；旧页关闭没有退订新目标资源。没有加入额外存储结构、宿主操作或评论功能。

首次合流修正的三个分支通过后，补固定／临时属性断言实际发现固定属性被后一个临时记录覆盖；该追加红灯保留，仅修正合流时保留已有固定属性，随后通过。

## 恢复重入

持有真实 SQLite 写锁使首次读状态失败，释放锁后连续执行两次普通重试点击。真实 stdio 子进程实际记录初次失败加两轮重试，共三次读状态；关闭首页并确认空副本 ACK 后，放行第二轮旧读取会复活页签，实际为 1 页而预期 0 页。

最小修正为恢复流程重入门控和在途重试禁用。相同契约现只有初次失败加一轮重试，没有第二轮迟到读取；关闭后数据库与页面保持空状态。不添加请求重试、固定等待或通用同步框架。

锁夹具最先使用进程内服务，同步 SQLite 同时阻塞了测试控制线程，等待错误提示超时；保留该准备失败。随后改为真实 stdio 服务，使锁等待与页面控制分属不同进程，再实际复现重入与页签复活；没有提高断言超时来掩盖问题。

## 初始化交互

首个干净文件在受审首读与订阅之间外改，资源补读提前显示首页；第二文件读取等待时，普通浏览器 focus 与键盘可进入该页，基线实际焦点断言红灯。此时恢复期间忽略界面变化，可能把新正文错误表示为副本已同步。

现在恢复流程结束前暂时禁用页面交互，阻止提前激活和编辑。相同资源时序下标准 focus 与键盘不能进入正文；完成后恢复正常编辑，新输入取得独立副本 ACK，源文件仍只含外部正文。不保存键盘焦点或改变主输入区。
