# 更新记录

本文件记录 suian-zcode-app-mcp 的用户可感知变化，版本独立于 common 和自动命名插件。

## [Unreleased] - 开发分支（#61 起，随正式集成定版）

新增会话置顶管理：可以把会话置顶、取消置顶，并单独列出置顶会话。

### 新特性

**会话置顶工具（pin/unpin/list_pinned_sessions）**

- `pin_session` / `unpin_session` 经公共网关调用原 Host `zcode-task` 的 `setTaskPinned` 置顶或取消置顶，写后从本机任务索引读回确认，未确认报 `pin_not_confirmed`，不猜默认值。
- `list_pinned_sessions` 只读本机任务索引列出置顶会话，默认排除归档与删除项、`include_archived` 可显式包含，workspace 过滤与分页规则同 `list_sessions`，不要求 Desktop 在线。
- 置顶与归档为正交状态：置顶只改变列表展示归属，不影响会话运行与历史；归档会话也可置顶。
- 公开工具数 12 → 15；置顶写声明幂等。宿主能力依据：官方 v3.15.1 `zcodeTaskServiceAdapter` 的 `setTaskPinned` 实现与 2026-10-15 网关探针实测（读写路径均可达）。

### 其他改进

**归档/复原读回改用精确查询**

- `archive_session` / `restore_session` 写后的索引读回从 `listSessions` 的子串查询 + 前 200 条切换为按 `task_id` 精确定位（与置顶读回同一 `listSessionStates` 路径）：标题引用目标会话 ID 的干扰行或列表截断不再可能把已写入的归档误报为 `archive_not_confirmed`。

**list_sessions 置顶优先排序**

- `list_sessions` 排序从纯更新时间改为 `pinned DESC, updated_at DESC, ...`：置顶会话排在最前，置顶段内部与非置顶段各自按更新时间从新到旧，对齐 Desktop 端"已置顶"分组的展示语义。`list_pinned_sessions` 行为不变。

## [0.5.0] - 2026-10-15

打开的工件面板在 `set_artifacts` 增删改后自动刷新，不再需要手动点"刷新"或重开面板。

### 新特性

**工件面板实时刷新（资源订阅）**

- server 宣告 `resources.subscribe` 能力并注册变更信号资源 `suian-artifacts://current`；工件实际写入（增删改、会话关联建链）且事务提交成功后向已订阅方推送 `notifications/resources/updated`，内容完全相同的 upsert 不推送，回滚不推送。
- 面板经 `window.zcode` 桥（ZCode 3.15+ 的 `zcode/resourceSubscribe` 扩展）订阅信号：到达时自动重拉列表与停留中的详情页，数据仍经只读的 `get_artifacts` 工具按当前会话拉取——不产生模型请求、不写聊天历史。
- 信号突发时列表与详情重拉均带合并（进行中收到新信号合并为完成后补拉一次），不放大对原 Host 的会话状态实时查询；初始化先订阅后首刷，丢信号窗口压至订阅在途毫秒级。
- 旧宿主或桥缺订阅能力时静默保持手动刷新，既有手动刷新、分页 revision 校验、主题订阅、分页续读行为不变。
- 研究依据与上游源码结论见 `docs/artifact-live-refresh-research.md`，验证证据见 `docs/artifact-live-refresh-evidence.json`（契约 6 例、回归 131/131、三轮审查修复循环）。

### 其他改进

- 市场、插件清单、包元信息和锁文件根版本同步为 `0.5.0`；运行时继续读取包版本。

## [0.4.2] - 2026-10-14

会话工件的显示名称跟随会话改名实时更新，不再停留在登记时的快照。

### Bug 修复

**会话工件的实时名称反查**

- `get_artifacts` 的 session 条目附带 `session_title`：读取时按任务索引（会话列表名称权威源）以会话 ID 反查的当前列表名称；反查结果不写回存储、不推高 revision。
- 会话改名后刷新工件列表、详情与 UserPromptSubmit 简表即显示新名；登记时的 `label` 标注保持不变。
- 反查不到（未入索引、已删除、标题为空）或索引库不可用（缺库、繁忙）时省略该字段并记一行 stderr 降级诊断，显示回退登记标注，不阻断工件读取。
- 同会话 ID 跨工作区存在多行时，取更新时间最新一行的名称。

### 其他改进

- 市场、插件清单、包元信息和锁文件根版本同步为 `0.4.2`；运行时继续读取包版本。

## [0.4.0] - 2026-10-12

用户提交时自动注入最近工件简表，并为其他类别保留展示空间。注入裁剪不改变完整工件数据。

### 新功能

**提交时的工件简表（Desktop 本地会话）（#51）**

- 在登记入口、统计与继承诊断后展示类型、名称、用途和引用，按更新时间降序选择最多 20 条。
- 每个非空类别优先保留最新最多 3 条，再按全局更新时间补足；字符不足时各类至少保留最新 1 条。
- 整个注入内容最多 9000 个 Unicode 码点，明确提示省略数量与字段截短；截短引用需先读取完整列表后再查询详情。
- 名称、用途和引用按 JSON 字符串转义，换行、管道和反引号不会伪造表格行；完整存储、工具查询和 GUI 列表不受裁剪影响。

> **验收边界**：118 项回归与正式 Hook 的隔离 MCP/SQLite 检查通过，规范轴与规格轴独立复核通过；实际 Desktop、真实模型行为与用户验收仍待进行。

## [0.3.0] - 2026-10-12

工件面板改版为可折叠分组列表，统一列表与单条详情查询，取消登记容量上限并支持分页。

### 改进

**工件面板改版（Desktop 本地会话）（#39）**

- 侧栏工件面板按类型提供可折叠分组列表与数量，增加方向图标、详情往返与时间信息。
- 统一 get_artifacts 的缺省列表与精确 ref 详情，点击会话实时查询原 Host 状态。
- 取消统计摘要模式的数量与字符总量上限，支持分页；start_session 自动登记双向创建关系。

> **验收边界**：109 项回归与真实 MCP、Chromium 交互检查通过；新版 Desktop 与用户验收仍待进行。

## [0.2.0] - 2026-10-12

新增当前会话的工件 demo，支持持久保存交付引用、历史断点分叉继承和原生只读侧栏。工具数量由十个增至十二个，原有会话和 GLM 工具继续可用。

### 新功能

**工件登记与历史继承（Desktop 本地会话）（#28、#29、#37）**

- get_artifacts 每次读取当前会话的最新列表、revision 和分类统计；set_artifacts 按 revision 校验并增量登记或移除 PR、关联会话、文件和链接。
- 工件保存在插件外置 SQLite，每会话最多 20 条、完整表示最多 12000 个 Unicode 码点；批次写入和容量检查保持原子性。
- 用户提交时注入一句及时登记的工具入口和统计，详细管理规则放在工具描述；工具回执提供更新后的统计。
- 同步 Stop Hook 保存不可变快照与断点映射，原生分叉按所选历史断点继承独立副本；缺快照时显示 snapshot_missing，子会话仍能继续管理工件。

**原生只读工件侧栏（Desktop 本地会话）（#31、#37）**

- 在侧边面板的“打开标签页”中选择“工件”，查看完整条目、revision 和统计，刷新时读取最新状态，无需模型参与。
- 按 ZCode 应用版本与 MCP Apps 能力提供页面资源；旧版继续保留工件工具和提交摘要。

### 其他改进

- 原生插件清单、包元信息和锁文件根版本统一升至 0.2.0；MCP 握手及远控客户端版本读取 package.json，并增加一致性契约验证。
- 增加更新记录和 README 版本入口，登记运行时版本的维护来源。

> **预览范围**：SQLite、MCP/stdio、同步 Hook 与隔离 Desktop 接线已验证；#30 的真实模型主动维护评估尚未执行，技术夹具不能代替用户验收。

> **侧栏条件**：要求 ZCode 应用版本至少 3.15.1、MCP Apps MIME 和目标会话的 MCP 连接就绪。#31 的冷会话首开仍可能受宿主连接尚未就绪的限制；已测宿主为 3.15.1.8093。

> **后续功能**：每请求唯一状态投影的完整版仍由 #36 跟踪，等待上游支持；当前提交摘要允许在运行时上下文中累积。

## [0.1.0] - 2026-10-11

原生插件初始基线提供会话查询、原 Host 操作与 GLM 套餐工具，复用公共网关和外置配置。

### 新功能

**原生会话 MCP（Desktop 本地会话）（#34、#35）**

- 提供会话检索、聊天历史，以及更名、创建、发信、压缩、归档和恢复工具；会话查询只读本机持久化数据，控制操作通过原 Host。
- 提供 GLM 套餐额度查询和经过本次用户许可、客户端确认表单的重置操作。
- 原生市场安装以 common 为依赖，自动注册 stdio 服务；技能按配置、会话、GLM 与排障职责拆分，支持旧源码接入迁移。
