# 工件面板增强：PR 实时状态与增删行数

本地标识：AP-02。GitHub Issue：[#68](https://github.com/ONEGAYI/ZCode-Plugins/issues/68)。

## 问题与交付

PR 工件在面板上只有单一 logo，开放还是已合并、是否草稿或冲突、相对主分支改了多少行都不可见，用户必须点开链接自行判断。

交付后，面板按标准刷新时机（列表刷新按钮、实时订阅信号、详情打开/刷新）由插件 server 端经 `gh` 拉取已登记 PR 的实时状态：state、草稿、可合并性与增删行数。首页每个 PR 行以状态 logo 替换现单一 logo（不配文字）：开放/已合并/已关闭/草稿/冲突五种视觉可区分；行尾右对齐显示相对主分支的增删行数（绿字 `+N`、红字 `-M`）。详情页同样显示状态与增删行数。

降级语义（用户裁决）：拉取出错（gh 失败、未认证、非 GitHub URL）时该条目不显示状态与数字，logo 回退默认；拉取超时时沿用旧数据正常显示，并在行尾右对齐追加黄色钟表 logo，tooltip 说明原因（如数据停留在何时、因超时未刷新）；无旧数据可沿用时超时按出错处理。

## 负责范围

新增 server 端状态拉取服务（gh 子进程调用、per-ref 内存缓存与时间戳、超时与错误分类）、面板读取状态的数据通道（面板专用，模型侧 `get_artifacts` 不产生网络副作用）、面板 PR 状态 logo 与行尾增删显示、超时钟表与 tooltip、契约测试（mock gh 子进程覆盖成功/超时/出错/缓存命中）。

## 验收条件

- [ ] 已登记的 GitHub PR 在面板显示与真实状态一致的状态 logo 与增删行数（真实 gh 验证）。
- [ ] 五种状态（开放/已合并/已关闭/草稿/冲突）logo 视觉可区分，首页不出现状态文字；冲突优先于开放显示，已合并/已关闭不再显示冲突。
- [ ] 行尾右对齐 `+N`/`-M` 绿红配色；详情页显示状态与增删行数。
- [ ] 模拟 gh 超时：旧数据保留显示，行尾黄色钟表 logo，tooltip 说明数据时间与超时原因；无旧数据时不显示状态、logo 回默认。
- [ ] 模拟 gh 出错/未认证/非 GitHub URL：状态与数字不显示，logo 回默认，不弹错误打断面板。
- [ ] 模型侧 `get_artifacts` 读取列表/详情不触发网络拉取，行为与现状一致。
- [ ] 刷新时机仅限面板标准刷新（手动刷新、订阅信号、详情打开/刷新），不额外轮询。

## 设计要点

- 状态通道为面板专用：`get_artifacts` 是模型高频读取路径，网络拉取放在单独的面板侧调用（新工具或 UI 专用通道），避免模型每次读取工件都付出网络成本。
- 缓存 per-ref 带成功时间戳；超时返回旧值加 stale 标记；建议拉取超时上限在秒级，测试以注入时钟/子进程桩验证，不依赖真实网络抖动。
- gh 查询字段：`state`、`isDraft`、`mergeable`（CONFLICTING 映射冲突）、`additions`、`deletions`；非 GitHub 域名的 ref 直接走出错路径，不起子进程。
- 五种状态由 open+draft/open+conflict/open/merged/closed 归并；优先级 merged、closed > conflict > draft > open。
