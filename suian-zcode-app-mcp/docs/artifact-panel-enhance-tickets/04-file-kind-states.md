# 工件面板增强：文件/文件夹图标区分与缺失第三态

本地标识：AP-04。GitHub Issue：[#69](https://github.com/ONEGAYI/ZCode-Plugins/issues/69)。

## 问题与交付

文件类工件目前一律使用文件 logo：登记的文件夹路径与普通文件视觉不可辨，路径已被删除或移动的条目也和有效条目长得一样，用户点进去才发现路径失效。

交付后，插件 server 在读取工件时对 file 条目做 stat 探测，返回目录标记与缺失标记；面板据此区分三种视觉态：文件夹使用文件夹 logo、普通文件使用现有文件 logo、路径不可访问（不存在）时在原图标样式基础上灰化显示。

## 负责范围

get 读取路径上的 file 条目 stat 探测与字段附加、面板三类图标渲染与灰化样式、契约测试（真实临时目录覆盖目录/文件/缺失路径）。

## 验收条件

- [ ] 登记的文件夹路径显示文件夹 logo，普通文件显示文件 logo，二者视觉可区分。
- [ ] 登记后删除该路径，面板刷新后条目图标按原图标样式灰化；路径恢复后刷新灰化消除。
- [ ] 缺失判定仅由"路径不存在"触发；stat 因权限或临时不可用等其它错误失败时不误判缺失、不灰化。
- [ ] stat 探测失败不阻塞 get_artifacts 正常返回（探测降级为未知态，工具响应完整）。
- [ ] 面板首页与详情页图标一致区分三态。

## Blocked by

无，可与 [#67](https://github.com/ONEGAYI/ZCode-Plugins/issues/67)/[#68](https://github.com/ONEGAYI/ZCode-Plugins/issues/68) 并行。

## 设计要点

- 探测发生在 server 读取路径（`get_artifacts` 列表与详情），面板不自行探测；探测结果不入库，每次读取实时判定。
- ENOENT 判缺失；其它 stat 错误一律按未知处理（显示为存在态，不灰化），避免网络盘或权限抖动造成误报。
