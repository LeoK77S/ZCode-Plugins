# 工件面板增强：用文件资源管理器打开

本地标识：AP-05。GitHub Issue：[#71](https://github.com/ONEGAYI/ZCode-Plugins/issues/71)。

## 问题与交付

文件类工件在面板上只能看到路径文本，想定位到磁盘上的实际位置必须手动复制路径再打开资源管理器。

交付后，文件与文件夹条目的详情页提供"用文件资源管理器打开"操作：文件条目打开其所在目录并选中该文件；文件夹条目打开该文件夹本身。路径缺失（AP-04 的缺失态）时按钮灰化不可点击。

宿主 MCP app 桥的 openLink 只放行 http(s)，`file://` 被宿主明确拒绝，因此该操作经页面 `callTool` 调用插件新增的本机定位工具，由 server 进程调用系统命令实现：Windows `explorer /select,<path>`（文件）与 `explorer <path>`（文件夹）、macOS `open -R` 与 `open`、Linux `xdg-open`。

## 负责范围

新增本机定位工具（工具 schema、跨平台命令分支、错误回报）、面板详情页按钮与灰化、工具权限边界测试。

## 验收条件

- [ ] 文件条目点击后资源管理器打开其所在目录并选中该文件（Windows 真实验收）。
- [ ] 文件夹条目点击后打开该文件夹本身。
- [ ] 缺失路径条目的打开按钮灰化不可点击（复用 AP-04 缺失态）。
- [ ] 工具仅接受当前会话已登记 file 工件的 ref：server 在当前会话工件表中解析 ref 后执行，未登记路径与非 file 条目直接拒绝，不接受任意路径参数。
- [ ] 打开失败（系统命令非零退出等）在面板行内回报错误，不静默。
- [ ] 三个平台命令分支在测试中以子进程桩验证调用形态；非当前平台分支不执行。

## Blocked by

[#69](https://github.com/ONEGAYI/ZCode-Plugins/issues/69)（缺失态判定驱动按钮灰化）。

## 设计要点

这是工件区第一个操作本机资源的工具：参数只收 ref，路径必须先在当前会话工件表中命中 file 条目才执行，把可打开路径收敛为"已登记工件"而非任意输入；工具描述中明示该边界，与"工件引用不构成授权"的既有约定衔接——本工具只执行用户在面板上的显式点击。
