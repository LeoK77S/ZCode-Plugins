# local-only 通过显式 Desktop 补丁接入现有网关，并纳入 setup

**状态**：2026-10-21 用户已裁决产品方向、版本范围、补丁作用目标、模式切换与退出安排；实现和兼容性尚未验证。

## 背景

3.16 Desktop 在 WebSocket 连接前执行账号检查、HTTP 设备注册和取令牌；只配置本地 WebSocket 不能满足离线冷启动。现有公共网关已有 local-only 握手、心跳和原 Host RPC，客户端不要求官方上游在线，安装器则主动拒绝 V2 与 local-only 的组合。

## 决定

- 首轮仅适配 Windows 3.16.2 的一个明确发行运行包，匹配具体包摘要；不把公开源码快照与发行包视为字节等同。
- 在 Desktop 增加显式启用的本地模式，优先复用现有网关和业务运行代码。不另起 CLI app-server，不以同目录模拟原 Host 附着。
- 交付纳入公共 setup：用户选择 local-only，Agent 调用补丁脚本完成预检与准备，对指定原安装目录备份后应用，继续使用原快捷方式。setup 技能与安装脚本允许按该目标修改。
- Agent 交付外部应用命令，由用户关闭 ZCode 后执行并自行重开；不强退当前宿主，不增设后台等待助手。
- 模式开关与应用包是否已 patch 分开。切回 relay 时保留补丁且恢复原账号/官方远控流程；提供独立完整还原命令。
- 验收要求无 ZCode 登录态且官方远控不可达时冷启动和网关重启恢复；模型服务可达性另行说明。首轮只以 MCP 闭环为完成条件，命名与评论分别后续开票。

## 影响与取舍

该选择使 local-only 进入正常产品安装流程，也引入按 Desktop 运行包维护补丁的责任。未知版本、摘要不符、宿主尚未退出、备份或写入失败必须明确失败，不能按模糊文本命中继续覆盖应用；升级后按新包重新核对，不自动套用旧补丁。

测试始终使用隔离应用副本、独立 Desktop/CLI/插件/网关数据和受控工作区。应用包副本、备份、令牌和原始日志不入库。静态可接入的判断不能代替原生验证，已有旧版 local-only 记录也不构成 3.16 验收。

若原网关运行代码无法通过实际契约，应先提交具体失败证据和必要变更范围，不能提前重写公共实现。设计事实与用户裁决见 [设计澄清](../local-only-design.md)。
