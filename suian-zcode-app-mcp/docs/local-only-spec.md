# Windows ZCode 3.16.2 local-only 产品接入规格

**状态**：2026-10-21 用户已确认范围和“5 张首轮票＋2 张后续票”的划分，并授权发布 Issues、推送文档及通过 PR 合入 dev。功能实施、真实安装 patch 和兼容性验收尚未执行。


**后续进展**：单包实施与隔离验收见[开发集成总验收](local-only/09-development-acceptance.md)；多版本管理扩展见[自动路由规格](local-only-routing-spec.md)。本文保留首轮立项时的范围与状态，新增路由不代表新增真实支持包。

设计依据见 [设计澄清](local-only-design.md)，长期选择见 [ADR 0003](adr/0003-local-only-desktop-patch.md)，实施顺序见 [开票索引](local-only-tickets.md)。

## 问题与目标

原版 3.16 Desktop 在连接 WebSocket 前检查账号并经 HTTP 注册设备、获取令牌，单独将 WebSocket 指向本地网关不能满足离线冷启动。现有网关已具备本地握手、心跳和原 Host RPC，插件客户端也支持 local-only 就绪判断；这些静态条件尚未在补丁版 3.16 上完成验证。

本次目标是将固定 Windows 3.16.2 运行包的 Desktop 补丁纳入现有 setup。用户选择 local-only 后，Agent 准备补丁和外部应用命令；用户关闭 Desktop 后执行，再通过原快捷方式重开。网关和业务运行代码优先直接复用。

**首轮成功标准**：没有 ZCode 账号登录态且官方远控服务不可达时，补丁版能够冷启动并接入原 Host；网关重启后可恢复；MCP 创建、提交输入、改名、历史读取闭环成立；可以切回 relay，也可以完整还原。

## 用户故事

1. 作为使用本机功能的用户，我希望 setup 提供 local-only 选择，以便不连接官方远控服务也能操控已有桌面会话。
2. 作为首次配置的用户，我希望 Agent 检查应用版本、路径和补丁状态，以便知道当前安装包是否受支持。
3. 作为正在与 Agent 对话的用户，我希望先收到准备完成后的外部命令，以便自行关闭 ZCode 后应用补丁，不丢失当前操作安排。
4. 作为日常使用者，我希望继续使用原快捷方式，以便不维护第二份长期应用副本。
5. 作为无 ZCode 登录态的用户，我希望本地远控可启动并在断线后恢复，以便账号和官方远控故障不阻断本地链路。
6. 作为需要手机远控的用户，我希望切回 relay 时保留原账号鉴权和官方连接流程，以便两种模式有明确边界。
7. 作为需要撤销补丁的用户，我希望独立还原命令恢复匹配的原包，以便能够回到原版运行状态。
8. 作为遇到应用升级的用户，我希望旧补丁在新包上明确报告不支持，以便不会被误改。
9. 作为执行验证的开发者，我希望有可复现的隔离环境和证据字段，以便测试不触及日常会话、凭据及网关。
10. 作为复现方案的朋友，我希望有从环境准备到诊断、切换和还原的指南，以便按步骤核对实际结果。

## 模块边界与状态

**Desktop 补丁**只改变显式本地模式下的远控授权和连接生命周期。不修改模型服务的账号或套餐授权，也不伪造官方认证成功；Host、会话持久化和既有 RPC 语义继续由原宿主管理。

本地模式需要覆盖启动检查、设备身份取得、取令牌、重连和账号通知。使用本地设备身份及本机网关，不创建官方上游连接；本地分支不得被账号退出通知误关。具体补丁点以目标发行包实际产物为准，不依赖公开快照的行号或猜测压缩变量。

**公共网关和客户端**维持现有 connectHost、control_token、健康字段及 Host RPC 接口。先使用未修改的网关字节验证。若实际发现不兼容，记录具体失败及最小修改范围，再调整对应任务，不提前重写协议或创建第二套网关。

**安装期工具**负责目标包识别、状态、准备、备份、应用和还原，以及公开的成功/失败回执。实现可沿现有 CLI、安装期入口和发布构建组织，不另建插件项目，不将 Desktop 运行包或个人数据打入插件 ZIP。

**setup/configuration/debug 技能**负责引导 Agent 选择模式、定位实际 Desktop、调用工具并解释状态。操作细节由脚本执行，不让 Agent 临时拼接替换压缩代码的命令。

| 应用包与配置 | 预期行为 |
| --- | --- |
| 原包，未启用本地开关 | 原版 relay 行为 |
| 已 patch，未启用本地开关 | 原版账号和官方远控链；补丁存在不等于启用本地模式 |
| 已 patch，显式 local-only，匹配回环网关 | 不依赖 ZCode 登录态或官方远控 HTTP/WS，复用本地原 Host |
| 未支持/摘要不符的包，请求 local-only | 明确拒绝应用，不尝试模糊匹配，也不静默切为 relay |
| 已准备后应用包发生变化 | 拒绝应用过期候选，不覆盖升级后的包 |
| 还原时当前包不再匹配本工具记录 | 明确冲突，不用旧备份覆盖未知新版本 |

模式必须由显式配置决定，不因临时联网失败自动切换。local-only 只连接回环端点，RPC 保留既有令牌校验和浏览器 Origin 拒绝。

## 产品 setup 流程

1. **预检与准备**：核对安装路径、应用版本、包摘要、当前模式和补丁/备份状态。首次及重复调用给出真实状态；准备阶段不改写运行中的应用包，不强退 Desktop。
2. **交付外部命令**：输出精确目标、准备结果、命令与预期回执。用户自行关闭该安装目录的全部 Desktop/相关运行实例，再从外部执行。
3. **应用与激活**：外部脚本重新核对受测输入及进程退出条件，完成已验证备份、应用与必要配置激活。失败时报告真实状态，按本次拥有的备份与配置恢复；不能留下成功或就绪假象。
4. **重开与验证**：用户用原快捷方式重开，检查应用取得正确模式和网关地址、desktop_ready、原 Host 探针与本机插件连接。仅广播环境变量不算已运行进程生效。
5. **切换与还原**：切回 relay 不重写包，按现有远控暂停/重载约定更新模式；完整还原另走外部命令，并核对恢复后包摘要和配置。不能擅自退出用户宿主。

目标路径、版本、输入摘要、备份可用性、运行实例、文件权限和写入失败属于安装外部边界。校验集中于这些边界，不在业务内部增加无依据的回退或吞错。恢复失败须保留可诊断证据，不宣称已恢复。

新补丁工具、所需资源和技能须进入公共插件正式构建；验证安装包自包含及独立缓存定位，不在发布缓存 npm ci、link.mjs 或现场修链接。本轮只开票，不改变现有 release/marketplace 版本。

## local-only 测试环境的搭建要求

环境搭建必须先于补丁实现，交付可执行入口和逐步说明。不能以“设置过变量”代替实际解析路径证据。

| 层 | 要求 |
| --- | --- |
| 运行对象 | 固定 Desktop exe、resources/app.asar、加载的 main/host、内嵌 CLI、Node、原包和补丁包摘要；公开源码 SHA 单独记录 |
| Desktop 数据 | 核对 ZCODE_DATA_BASE_DIR、ZCODE_DESKTOP_HOME_DIR、ZCODE_DESKTOP_USER_DATA_DIR；独立应用身份/sessionData，避免单实例锁转交到日常窗口 |
| CLI 数据 | 同时隔离 HOME、USERPROFILE、APPDATA、LOCALAPPDATA，并明确 ZCODE_STORAGE_DIR、ZCODE_SESSION_DB_PATH；任务索引与 CLI 会话库都要核对实际位置 |
| 网关 | 专属 config.json、控制令牌、回环端口和进程；不占用、重载或停止日常服务 |
| 插件与工作区 | 隔离安装记录、外置配置、Hook/MCP 数据和工作区；记录实际加载入口及发布包/源码摘要 |
| 登录态 | 不默认复制真实登录凭据；无 ZCode 登录态是必验条件 |
| 网络 | 用可核实的官方远控不可达条件验证；记录连接/请求证据，不能仅以 upstream_connected=false 证明未发起过官方请求 |
| 模型 | 可用受控本地服务检验确定性输入输出；真实模型另记网络条件，不把合成回复当成真实模型效果 |
| 收尾 | 关闭本次进程、释放本次端口并恢复本次拥有的配置；日常应用包、会话与网关不变 |

历史 3.16 实验曾因仅隔离 Desktop 而触及默认 CLI 库。新验证要在启动前证明目录/配置归属，启动后核对实际库与测试会话归属；发现越界立即停止该轮，保留真实失败，不用覆盖日常库回滚掩盖问题。

## 验证层级与完成条件

**契约层**：使用真实临时文件、回环 HTTP/WS 和脚本公开入口检验补丁状态、包匹配、应用/还原、V2 握手、恢复和模式切换。新增可执行行为遵循先红后绿；不用镜像实现的测试替代行为验证。

**原生层**：实际运行固定发行包和受控隔离插件，验证无登录态冷启动、网关重启恢复、用户重开 Desktop、原 Host 调用及 MCP 闭环。原包在相同条件下的失败基线与补丁后的结果分别保留。

**产品流程层**：通过真实构建插件的 setup/configuration/debug 路径完成准备、外部应用、普通快捷方式启动、切回 relay和完整还原。relay 官方端若不具备实际联网/账号条件，保留未验状态，不用夹具冒充线上验收。

MCP 首轮至少检查：start_session 创建并首次提交合成输入，send_message 获得 Host 受理回执，rename_session 改名并读回，list_sessions/read_session 核对会话与内容，网关重启后再次查询和提交。实际名称以当前 MCP 工具清单为准，不自行增加新工具。Host ACK 只证明输入受理；模型完成、真实 Stop 和评论不是同一验收事实。

完成 LO-01 的调查不自动证明 LO-02 所需运行包/补丁点可用；后续票除 Issue 依赖外，须满足具名运行条件。首轮在 LO-01 至 LO-05 均满足各自验收后完成，用户产品验收另记。

## 证据与指导交付

最终指南覆盖：支持包和依赖准备、隔离目录/配置、原版失败基线、setup 选 local-only、Agent 准备、外部应用、正常重开、MCP 检查、故障定位、切回 relay、完整还原与清理。

失败诊断至少区分包不支持/摘要变化、宿主仍运行、备份或写入失败、环境未生效、网关未就绪、Host 未附着与模型服务不可达。指南提供可复制的模板参数，不写本机个人路径、令牌或会话标识。

每份证据记录：代码 SHA、运行包/插件/网关摘要、OS/Node/Desktop/CLI 版本、加载路径、模式与隔离配置摘要、命令、日志、退出码、预期/实际、未验条件。原始日志、包副本和备份留在忽略的实验目录，入库只放脱敏最终证据。

长流程首次运行即保存日志和退出码。相同受测输入、环境和范围的有效记录复用；新增失败假设、输入或环境变化时先说明原因，优先重跑相关范围，不因提交、PR 或合并阶段切换重复全量。

## 范围之外

- 未明确适配的其它 Windows 包、所有 macOS/Linux 版本和未来应用版本。
- 通过本地模式提供官方手机远控，或将“远控无需联网”扩展为“模型和套餐服务全离线”。
- 修改模型授权、消耗重置卡、自动争抢官方 terminal 或创建新的 CLI app-server。
- 修改只读 sources、安装其依赖、分发完整 Desktop 包或处理用户真实会话库。
- Agent 强制退出/重启当前宿主、后台等待补丁助手、无条件覆写升级后的应用。
- 将真实 Stop 自动命名或侧栏评论计入本轮 MCP 完成条件；完整并发评论继续遵循其原独立议题。
- 本轮文档合入不等于授权执行功能开发、实际安装 patch 或正式发布。
